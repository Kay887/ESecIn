Database setup SQL & access controls

Run once in Supabase SQL Editor. Then enable Realtime for this table if the publication statement reports that it already exists.

create table if not exists public.ld_tracker_state (
  id text primary key check (id = 'india'),
  state jsonb not null default '{"items":[],"reviews":[],"comments":[],"notifications":[],"activity":[],"meta":{}}'::jsonb,
  updated_at timestamptz not null default now(),
  updated_by uuid references auth.users(id)
);

alter table public.ld_tracker_state enable row level security;
drop policy if exists "Team members can read tracker" on public.ld_tracker_state;
drop policy if exists "Team members can create tracker" on public.ld_tracker_state;
drop policy if exists "Team members can update tracker" on public.ld_tracker_state;
create policy "Team members can read tracker" on public.ld_tracker_state
  for select to authenticated using (true);
create policy "Team members can create tracker" on public.ld_tracker_state
  for insert to authenticated with check (true);
create policy "Team members can update tracker" on public.ld_tracker_state
  for update to authenticated using (true) with check (true);

alter publication supabase_realtime add table public.ld_tracker_state;

Security: invite only the founding team / named operators in Supabase Auth, disable public sign-ups, and do not use a service-role key in this HTML. The included baseline policy lets any authenticated team member edit the shared tracker. Use stricter per-role policies before broad rollout.

Concurrency note: this first live-sync version stores the portfolio in one JSON document and merges independent new comments / initiative changes where possible. Avoid editing the same initiative simultaneously. For larger teams or strict audit requirements, move to separate initiatives, comments, mentions and notifications tables with per-record conflict handling.

Live sync needs internet and a Supabase project. Local mode remains available without it.
